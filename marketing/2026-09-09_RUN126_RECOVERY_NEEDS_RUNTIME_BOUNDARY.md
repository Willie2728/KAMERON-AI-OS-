# KAM-TXT-105 — A Recovery Pilot Needs a Place to Fail

## Customer Truth
A recovery plan without a runtime or integration boundary is still a thought experiment. The buyer should identify where the fault can actually be exercised before contact is treated as a qualified recovery-pilot request.

## Hook
**A recovery pilot needs a place to fail.**

## Deployable copy
Define the failure class and scenario, the state that must survive, the state-consistency receipt, the side effect that must not repeat, the no-duplicate receipt, resume authority, recovery objective, and the runtime / SDK / storage / identity / provider / gateway boundary actually available for the bounded test.

## CTA
Name the environment available for the test, then copy the Bounded Recovery Proof Brief before sharing a work email.

## Claims boundary
A buyer-entered integration boundary is planning context only. It does not prove KAMERON is integrated or deployed, that a fault has been exercised, that state is current, that external side effects will not repeat, or that a recovery objective has been achieved.
